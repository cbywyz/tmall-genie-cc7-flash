# 10 · 踩坑合集

按「坑 → 现象 → 根因 → 解法」整理，全部真实踩过。

---

## 一、刷机阶段

### 1. MTKClient 无限卡在 `Reconnecting to preloader`

- **现象**：设备管理器能看到 MTK 设备，但 GUI 一直重连，无法握手
- **根因**：驱动不匹配，MTK 设备被错误的驱动接管
- **解法**：装 **UsbDk 1.0.22**，然后用 **Zadig** 给 `VID_0E8D&PID_2001` 装 **WinUSB** 驱动

### 2. 进不去 BROM

- **现象**：按键组合试了很多次，MTKClient 读不到芯片
- **根因（按概率）**：① 数据线只能充电 ② UsbDk 没装/没重启 ③ 断电不足 10 秒 ④ 按键时机不对（先按后通电）⑤ USB 口问题
- **解法**：先用手机验证线能传数据 → **USB 全程连着** → 断电 10 秒以上 → 通电 → **立刻**按住四键 → 等 MTKClient 读到芯片再松手。
  **不是**"先按住四键再插线"，顺序反了会一直失败。重试就整段重来（重新断电 10 秒），不要中途拔插数据线。

### 3. Magisk 塞 `system/app` 后 root 失效

- **现象**：Magisk 图标在，但授权弹窗不出、「超级用户」灰色
- **根因**：Magisk 守护进程的启动路径依赖普通应用的安装方式
- **解法**：**必须 `adb install` 装成普通应用**（实测塞 system 两次都失败）

### 4. 改完 `build.prop` 没效果

- **现象**：`ro.adb.secure=0` 改了，adb shell 还是 `error: closed`
- **根因**：① treble 设备上 `prop.default` 优先级更高 ② 阿里在 `adbd` 二进制里加了隐藏开关 `persist.sys.adb.enabled`
- **解法**：`build.prop` 加 `persist.sys.adb.enabled=1`，同时改 `system/etc/prop.default` 的 `ro.secure` / `ro.debuggable` / `ro.adb.secure`

### 5. CRBuilder 改了镜像大小 → 开机进 fastboot

- **解法**：镜像大小保持默认 1.34 GB，不要改

### 6. 反向分析 `adbd` 时 strings 偏移对不上

- **根因**：`strings -t x` 给的是**文件偏移**，ARM 代码引用的是**虚拟地址**
- **解法**：按 PT_LOAD 段换算 `VA = p_vaddr - p_offset + file_offset`

## 二、优化阶段

### 7. 🔴 冻结预装后无限卡开机 logo

- **现象**：卡 logo，WiFi adb 失联，USB adb `offline`
- **根因**：冻结了声明 `android.intent.category.HOME` 的包（`genie.smartapp`、`genie.children`），`PackageManager` 返回 `applicationInfo == null`，`AMS.systemReady()` 空指针崩溃
- **解法**：见 [09 · 开机循环救援](09-开机循环救援.md)，root shell 改 `package-restrictions.xml`，8 分钟无损修复
- **预防**：冻结前必跑 `dumpsys package <包名> | grep -c 'android.intent.category.HOME'`

### 8. `pm disable-user` / `pm uninstall` 报 unknown command

- **根因**：阿里阉割了 `pm` 的写操作子命令（usage 文案还留着，函数删了）
- **解法**：改用 `cmd package suspend` / `cmd package unsuspend`（走另一条直达系统服务的路径）

### 9. `cmd package suspend` 回显成功但实际没冻上

- **现象**：脚本打印了很多 `new suspended state: true`，但最终 `grep -c` 只有 11 个
- **根因**：中途 `system_server` 重启，命令报 `Failure calling service package: Broken pipe (32)`，部分包没生效
- **解法**：**只信** `grep -c 'suspended="true"' /data/system/users/0/package-restrictions.xml`，数字对不上就补刷

### 10. 进桌面后触摸完全失灵

- **根因**：阿里 `children/AdultHomeActivity` 抢到前台并 CPU 空转，吞掉所有触摸事件。**不是触摸层坏了**
- **诊断**：`dumpsys window | grep mCurrentFocus` + `top` 看 CPU
- **解法**：`am force-stop com.alibaba.ailabs.genie.children` + 拉起第三方桌面

### 11. `genie.iot` / `aligenie.ags` 冻结后进程还在

- **根因**：阿里自己的常驻服务，`suspend` 后仍被系统拉起，`am force-stop` 也无效
- **解法**：放弃，并**撤销其挂起状态**，避免留下「标记挂起但进程还在跑」的半吊子状态

### 12. `cmd package set-home-activity` 设了默认桌面，HOME 键还是回阿里桌面

- **根因**：阿里在系统层强行拉起 `AdultHomeActivity`，绕过 HOME 意图解析（`preferred-activities` 里写了 `always="true"` 也压不住）
- **解法**：Magisk 开机脚本在 `boot_completed` 后主动拉起第三方桌面（见 [08](08-系统优化-冻结预装.md)）。**彻底改需要组件级禁用，有风险，未实施**

## 三、工具与环境

| 坑 | 解法 |
|---|---|
| `Magiskpatcher.exe` / `mtkclient.exe` 被 Defender 删掉 | 把工具目录加入 Defender 排除列表 |
| Win11 打不开 rar | 自带 `C:\Windows\System32\tar.exe` 是 bsdtar，可 `tar -xf x.rar` |
| 中文路径下工具报错 | 工具目录用纯英文无空格路径 |
| `adb push` 偶发 `protocol fault: failed to read stat response` | 设备 adbd 不稳定时会出现；改用 `adb shell su` + heredoc 直接写文件 |
| 设备 adb 枚举但 `offline` | 先 `adb kill-server` 再 `adb start-server`；框架未起来时 `offline` 属正常 |

## 四、一句话总结

1. **备份没做完，不许写任何分区。**
2. **改系统状态前先查 HOME 声明，不凭包名语义猜。**
3. **禁止批量冻结**：单个 → 重启 → 校验 `sys.boot_completed=1` → 下一个。
4. **改 `/data/system` 下文件用 `cat` 原地覆盖**，别 `mv`、别重新 push。
5. **`system_server` 崩了不等于砖**，root shell 永远有救。
