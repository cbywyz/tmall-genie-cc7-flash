## 🔴 先记住这条，否则必砖

> **冻结任何系统包之前，必须先查它是否声明了 `android.intent.category.HOME`。**
> 冻结到「桌面候选包」= `system_server` 每次开机必崩 = 无限卡开机 logo。

判断命令（唯一可信）：

```bash
adb shell "dumpsys package <包名> | grep -c 'android.intent.category.HOME'"
```

- 返回 `0` → 可以冻结
- 返回 `>0` → **绝对不能冻**

### CC7 上实测的禁区

| 包名 | 里面的 HOME 组件 |
|---|---|
| `com.alibaba.ailabs.genie.smartapp` | `genieboot.activity.BootHomeActivity` |
| `com.alibaba.ailabs.genie.children` | `launcher.activity.AdultHomeActivity` |
| `com.alibaba.ailabs.genie.osupdate` | （也声明了 HOME 类目） |

**为什么冻结 HOME 包会让系统崩**（崩溃堆栈实录）：

```
java.lang.NullPointerException: Attempt to read from field
 'android.content.pm.ApplicationInfo android.content.pm.ComponentInfo.applicationInfo'
 on a null object reference
    at com.android.server.am.ActivityRecord.<init>(ActivityRecord.java:808)
    at com.android.server.am.ActivityStarter.startHomeActivityLocked(ActivityStarter.java:647)
    at com.android.server.am.ActivityManagerService.systemReady(ActivityManagerService.java:14815)
    at com.android.server.SystemServer.startOtherServices(SystemServer.java:1758)
```

包被挂起后，`PackageManager` 返回的 `ComponentInfo.applicationInfo` 是 `null`，`startHomeActivityLocked()` 构造 `ActivityRecord` 时直接空指针 → `system_server` 在框架启动最后一步必崩 → 开机动画永远 running。

## 为什么常规 pm 命令都不能用

阿里把这台设备的 `pm` **阉割过**：

```bash
$ pm disable-user --user 0 com.youku.iot
Error: unknown command 'disable-user'      # usage 里明明列着，函数被删了

$ pm uninstall -k --user 0 com.youku.iot
Error: unknown command 'uninstall'
```

`pm path` / `pm list packages` 这类**只读**命令正常，写操作全被摘掉 —— 防的就是用 adb 卸载预装。

### 可用通道：`cmd package`

`cmd package` 走另一条直达系统服务的路径，绕过被改的 `pm` 包装器：

```bash
adb shell su -c 'cmd package suspend com.youku.iot'
# Package com.youku.iot new suspended state: true
```

`suspend` 是**可逆**的（`cmd package unsuspend`），比 `uninstall` 更安全，且不需要重新签名系统。

## 正确的操作节奏（分批 + 重启验证）

> ⚠️ **不许一把梭 21 个。** 单个/小批 → 重启 → 校验 → 下一批。

### 第 1 步：扫描候选包

```bash
bash scripts/check-home-packages.sh <包名1> <包名2> ...
```

输出里带 ⛔ 的**一律跳过**。

### 第 2 步：分批冻结

```bash
bash scripts/freeze-safe.sh
```

脚本行为：每批冻结 → `reboot` → 轮询 `getprop sys.boot_completed` → 为 `1` 才继续下一批；失败立即停止。

### 第 3 步：核对真实生效数量

**别信 `cmd package suspend` 的回显顺序。** 中途 `system_server` 重启会出现：

```
cmd: Failure calling service package: Broken pipe (32)
```

这种包**没有真正冻结**，命令却可能看起来执行过了。唯一可信的校验：

```bash
adb shell su -c 'grep -c "suspended=\"true\"" /data/system/users/0/package-restrictions.xml'
```

数字对不上就补刷缺失的包。

## 顺手做的两项

### 动画缩放降到 0.5

```bash
adb shell settings put global window_animation_scale 0.5
adb shell settings put global transition_animation_scale 0.5
adb shell settings put global animator_duration_scale 0.5
```

对 1GB 内存的老设备，手感提升立竿见影。

### 第三方桌面：可选项，但实测不推荐

阿里在系统层强行把 `AdultHomeActivity` 拉为前台，`cmd package set-home-activity` 压不住。想让开机画面固定到第三方桌面，只能用 Magisk 开机脚本兜底：

```bash
adb push scripts/99-dangbei-home.sh /data/adb/service.d/
adb shell su -c 'chmod 755 /data/adb/service.d/99-dangbei-home.sh'
```

删除该文件即完全撤销，不改系统、不冒砖风险。

**但这套流程最终没有采用**，实测结论如下：

| 维度 | 原桌面（`genie.children/AdultHomeActivity`） | 当贝等第三方桌面 |
|---|---|---|
| 语音、儿童模式、IoT 入口 | 完整，与固件配套 | 被盖住，需要另行找回入口 |
| 开机落点 | 天然就是它，无需任何脚本 | 要靠开机脚本硬拉，且 HOME 键仍可能回阿里桌面 |
| 后台开销 | 0 | 当贝会自启 `com.dangbei1.tvlauncher` + `:xmpushservice` 两个进程，实测合计约 **130MB** |
| 精简收益 | — | 省不了多少：能吃掉的预装已经冻完了，剩下的都是 HOME 候选或阿里常驻服务 |

**结论**：在「无法大幅精简」的前提下，把默认桌面换成第三方是净亏 —— 遮挡原生功能，还要额外养一个后台进程。撤掉开机脚本、回到原桌面即可，第三方桌面 APK 保留在应用列表里，需要时手动打开。

```bash
# 撤销（本次实际执行的动作）
adb shell su -c 'cp /data/adb/service.d/99-dangbei-home.sh /data/local/tmp/99-dangbei-home.sh.bak'
adb shell su -c 'rm /data/adb/service.d/99-dangbei-home.sh'
adb shell su -c reboot
```

## 冻不住的那些（别再白费力气）

| 现象 | 结论 |
|---|---|
| `genie.iot` / `aligenie.ags` 冻结后进程仍在 | 阿里自己的常驻服务，`suspend` 后仍被系统拉回；`am force-stop` 也无效。**已撤销其挂起状态，保持干净** |
| `smartapp` 常年吃 50~116% CPU | 它是 HOME 候选，不能冻。日志显示后台动画 `ImageLoader hit cache .../animation/*/default.png` 每秒重绘 6~8 次 |
| 内存长期只剩 27~70MB | 986MB 硬件上限 + 系统堆栈体量，清预装改不了量级 |
