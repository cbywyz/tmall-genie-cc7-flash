# 03 · 全量分区备份（唯一后悔药）

> 🚨 **备份没做完，不要执行任何写操作。**
> 这台设备没有官方救砖包，`system` / `boot` 写坏了，唯一的恢复路径就是这里的备份。

## 备份清单

用 MTKClient 按分区读取，实际备份了 17 个分区：

| 分区 | 大小 | 作用 | 优先级 |

| `system` | 1.34 GB | 系统分区，注入 APK 就改它 | 🔴 必须 |
| `boot` | 16 MB | 内核 + ramdisk，Magisk 补丁目标 | 🔴 必须 |
| `seccfg` | 256 KB | BootLoader 锁定状态 | 🔴 必须 |
| `recovery` | 16 MB | 恢复模式 | 🟠 强烈建议 |

| `proinfo` | 3 MB | 产品信息（序列号等） | 🟠 强烈建议 |
| `lk` / `lk2` | 384 KB ×2 | 引导程序（Little Kernel） | 🟠 强烈建议 |

| `odmdtbo` | 16 MB | DTBO / ODM | 🟡 建议 |

## 备份后立刻做三件事

### 1. 校验文件完整性

`system.bin` 必须是完整镜像大小（本例 1.34 GB），不是 0 字节或几 MB。逐个确认：

```bash
ls -l backup/
```

更严的做法是拿实际字节数跟预期清单逐个比对，而不是只看「文件有大小」：

```bash
python - <<'PY'
import os
d = r"backup"
expect = {
    "boot.bin": 16777216, "dkb.bin": 2097152, "expdb.bin": 10485760,
    "frp.bin": 1048576, "kb.bin": 2097152, "lk.bin": 393216,
    "lk2.bin": 393216, "logo.bin": 8388608, "nvram.bin": 5242880,
    "odmdtbo.bin": 16777216, "para.bin": 524288, "proinfo.bin": 3145728,
    "recovery.bin": 16777216, "seccfg.bin": 262144,
    "system.bin": 1438646272, "tee1.bin": 5242880, "tee2.bin": 5242880,
}
bad = {k: (v, os.path.getsize(os.path.join(d, k)))
       for k, v in expect.items()
       if not os.path.exists(os.path.join(d, k)) or os.path.getsize(os.path.join(d, k)) != v}
print("全部一致" if not bad else bad)
print("总字节:", sum(os.path.getsize(os.path.join(d, f)) for f in os.listdir(d)))
PY
```

预期总字节 `1533542400`。**只校验字节数不等于校验内容** —— 它能挡住最常见的截断/未写完，挡不住位翻转；要求更高就再跑一次 SHA-256 并与备份时记录比对。

### 2. 上传到云盘作为长期存档（主要副本）

备份统一放在云盘的固定目录，以后救砖直接从这里取：

| 位置 | 路径 | 性质 |
|---|---|---|
| 私有云盘 | `/AI空间/第三方智能体/<专属目录名>/天猫精灵CC7分区备份-20261103` | **唯一长期存档**，2026-11-03 归档 |

> `<专属目录名>` 因人而异，按自己账号下实际目录名替换；该目录是私有空间，别人拿到路径也访问不了。

上传后同样要做一次**逐项字节比对**：17 个文件、总计 `1,533,542,400` 字节，确认无缺失、无多余、无大小不符，才算归档完成。上传结束的进度提示不代表文件完整。完整清单见 [`reports/云盘存档清单.md`](../reports/云盘存档清单.md)。

### 3. （可选）再留一份离线介质

云盘是账号内的在线存储，账号异常、误删、限流都可能拿不到文件。手头有 U 盘 / 移动硬盘的话，1.4 GB 再放一份最稳。

## 恢复方式（出事时怎么用）

### A. 只恢复单个分区（最常见）

比如刷坏了 `boot`：

```
MTKClient → Write Partition → 选择 boot → 指向 backup/boot.bin → 写入 → 断电重启
```

### B. 恢复 system

同上，指向 `backup/system.bin`（1.34 GB，写回约几分钟，中途不要断线）。

### C. `nvram` 出问题（WiFi 打不开 / MAC 变 00:00:00:00:00:00）

写回 `backup/nvram.bin` 后重启，WiFi 恢复正常。

---

## 一个反直觉的点

**不要用「读全盘」代替逐分区备份。** 逐分区备份的好处是：出事时能只恢复坏的那一个，不用整盘回滚（整盘回滚会同时丢掉你在别的分区上做过的修改）。
