# 天猫精灵 CC7 开机循环事故 — 处置报告

日期：2026-11-03 12:16 ~ 12:26
设备：天猫精灵 CC7（TG_S2B / alps full_ailabs_s1l_8b / Android 8.1）
结论：**已完全修复，未清数据、未刷机、root 与已装应用全部保留**

---

## 一、现象

- 屏幕卡在天猫精灵开机 logo 不动
- WiFi <设备局域网IP>:5555 完全连不上
- USB adb 显示设备存在（`VID_0E8D&PID_201C` / `AILABS_S1L_8B`），但状态长期 `offline`

## 二、根因（有代码级证据，非推测）

`/data/system/dropbox/system_server_crash@1793679756473.txt`：

```
Process: system_server
java.lang.NullPointerException: Attempt to read from field
 'android.content.pm.ApplicationInfo android.content.pm.ComponentInfo.applicationInfo'
 on a null object reference
    at com.android.server.am.ActivityRecord.<init>(ActivityRecord.java:808)
    at com.android.server.am.ActivityStarter.startHomeActivityLocked(ActivityStarter.java:647)
    at com.android.server.am.ActivityManagerService.startHomeActivityLocked(ActivityManagerService.java:4492)
    at com.android.server.am.ActivityManagerService.systemReady(ActivityManagerService.java:14815)
    at com.android.server.SystemServer.startOtherServices(SystemServer.java:1758)
```

**链条**：
1. 优化时用 `cmd package suspend` 冻结了 21 个预装包；
2. 其中 `com.alibaba.ailabs.genie.smartapp`（含 `genieboot.activity.BootHomeActivity`）和
   `com.alibaba.ailabs.genie.children`（含 `launcher.activity.AdultHomeActivity`）**声明了 `android.intent.category.HOME`**，属于桌面候选；
3. 挂起状态下 `PackageManager` 返回的 `ComponentInfo.applicationInfo == null`；
4. `ActivityManagerService.systemReady()` → `startHomeActivityLocked()` 构造 `ActivityRecord` 时 NPE；
5. system_server 在框架启动末期必然崩溃 → 开机动画永远 running → 无限重启。

## 三、修复过程（非破坏性，全程约 8 分钟）

关键点：**system_server 崩了，但 adbd 和 Magisk 的 root 早于框架启动**，所以还能进 root shell 手术。

```sh
# 1. 停框架，防止 system_server 重启时用内存态覆盖文件
su -c 'stop zygote'

# 2. 备份原始状态文件
cp /data/system/users/0/package-restrictions.xml /data/local/tmp/pr.orig.xml

# 3. 去掉全部 suspended="true" 标记
sed 's/ suspended="true"//g' /data/local/tmp/pr.orig.xml > /data/local/tmp/pr.fixed.xml

# 4. 原地写回（cat 覆盖，保留 inode / 属主 / SELinux 上下文）
cat /data/local/tmp/pr.fixed.xml > /data/system/users/0/package-restrictions.xml

# 5. 校验后重启
grep -o 'suspended="true"' /data/system/users/0/package-restrictions.xml | wc -l   # 必须为 0
reboot
```

验证：`getprop sys.boot_completed` 返回 `1`，桌面 `com.dangbei1.tvlauncher` 正常起来。

> 恢复脚本已存本地：`fix_suspend.sh`（下次可 adb push 后 `su -c sh` 执行）

## 七、教训

1. **`cmd package suspend` 对系统预装是高危操作**：一旦碰到声明 HOME 的包，就是必然的 system_server 启动崩溃循环。
2. **改系统级状态前必须做「包 → HOME 声明」扫描**，不能凭包名语义判断。
3. **别一次性批量冻结 21 个**，应单个 → 重启 → 验证 `sys.boot_completed` → 下一个。
4. 这台设备无需进 recovery / BROM：Magisk root 在框架之前可用，`/data/system` 可直接手术。
