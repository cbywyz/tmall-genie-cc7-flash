   **不能冻结**（HOME 候选）。硬要治只能做组件级禁用实验，有再次搞挂开机的风险。

2. **`genie.iot` / `aligenie.ags` 停不掉**
   实测 `cmd package suspend` 后进程仍被系统拉回（阿里自己的常驻服务），`am force-stop` 也无效。
   已把这两个的挂起状态撤销，避免留下半吊子状态。

3. **内存是结构性瓶颈**
   986MB 总量，系统常驻占用 916~959MB，可用长期只有 27~70MB，`kswapd0` 频繁工作。
   这是硬件上限，清理预装只能改善体验，不能改变量级。

## 五、回滚手册（三档，按严重程度）

### A. 撤销全部冻结（开机后能用 adb 时）
```sh
adb shell su -c 'for p in $(dumpsys package | grep -oE "^ *Package \[[^]]+\]" | sed "s/.*\[//;s/\]//"); do cmd package unsuspend $p; done'
```
或直接按包名逐个 `cmd package unsuspend <包名>`。

### B. 撤销开机自动拉起
```sh
adb shell su -c 'rm /data/adb/service.d/99-dangbei-home.sh'
```

### C. **开机卡 logo 救援（system_server 崩溃循环时）**
根因仍是挂起包时，用这套（已实测可救）：
```sh
adb shell su   # 进 root shell
stop zygote
cp /data/system/users/0/package-restrictions.xml /data/local/tmp/pr.orig.xml
sed 's/ suspended="true"//g' /data/local/tmp/pr.orig.xml > /data/local/tmp/pr.fixed.xml
cat /data/local/tmp/pr.fixed.xml > /data/system/users/0/package-restrictions.xml
sync
reboot
```
关键点：`cat` 原地覆盖，保留 inode / 属主 / SELinux 上下文；不要用 `mv` 或重新 push。

## 六、铁律（下次再折腾时照做）

1. 改系统状态前，**先查 HOME 声明**，不凭包名语义猜。
2. **禁止批量冻结**；单个 → 重启 → 校验 `getprop sys.boot_completed` = `1` → 下一个。
3. 冻结类操作前后都留一份 `package-restrictions.xml` 备份。
4. 触摸失灵先看 `mCurrentFocus`，八成是某个僵死窗口抢了前台，不是触摸层坏了。
5. 这台设备的 root 在 `system_server` 之前就绪 —— **永远有救，不需要 recovery / BROM**。
